# Spec — Plan 1.5: Security & Resilience Hardening

| | |
|---|---|
| **Status** | v2 — revised after independent review (2026-10-07); approved for implementation |
| **Builds on** | [Plan 1 spec](2026-10-07-plan-1-catalog-api-spec.md) (all of its requirements still hold) |
| **Trigger** | Security check of 2026-10-07: 23 reachable known vulnerabilities; no rate limiting, timeouts or concurrency limits |

RFC 2119 keywords. Requirement ids `H-…`, acceptance criteria `HAC-…`.

## 1. Goal

Make the read-only API safe to expose to the internet **on its own**, so it stays correct
and responsive under abuse even before Cloudflare and Caddy sit in front of it (Plan 7).
Those outer layers are defence in depth, not the only line.

**In scope:** one client (or a small botnet) flooding the API; slow clients holding
connections; slow or stuck queries; known-vulnerable dependencies; CI supply-chain drift;
a compromised process escalating inside its container; logs filling the disk.

**Out of scope:** authentication (Plan 3), upload limits (Plan 4), TLS/HSTS, compression
and edge rules (Plan 7, in Caddy/Cloudflare), large distributed DDoS (Cloudflare).

## 2. Deployment topology this spec assumes

```
Browser → Cloudflare → Caddy ─┬─▶ Next.js (web) ──server-side fetch──▶ API
                              └─▶ API
```

Only Caddy talks to Cloudflare; only Caddy and the web container talk to the API, over
the compose network. This determines how the API learns the real client IP (§4).

---

## 3. Dependencies (H-DEP)

- H-DEP-1: `go.mod` declares `go 1.26.6` (first release fixing every reported standard-library vulnerability).
- H-DEP-2: `golang.org/x/crypto` ≥ v0.56.0, `github.com/moby/go-archive` ≥ v0.3.0.
- H-DEP-3: `govulncheck ./...` reports **no reachable vulnerabilities**; CI fails if it ever does.
- H-DEP-4: The Docker build stage uses the floating `golang:1.26-alpine` tag and CI builds with `docker build --pull`, so rebuilds pick up patches and a stale cached image can't fail on the `go 1.26.6` requirement.

## 4. Client IP (H-IP)

- H-IP-1: By default the client IP is the host part of `RemoteAddr`; `X-Forwarded-For` (XFF) is **ignored**, because anyone can forge it.
- H-IP-2: `TRUSTED_PROXIES` (comma-separated CIDRs, default empty) lists proxies whose XFF is trusted. When `RemoteAddr` is inside a trusted CIDR, the client IP is the **right-most** XFF address that is not itself trusted. All XFF header lines are considered, in order (`Header.Values`). If no entry qualifies, `RemoteAddr` is used.
- H-IP-3: Addresses are parsed with `net/netip`, accepting `ip`, `ip:port` and `[ipv6]:port`; IPv4-mapped IPv6 is unmapped (`::ffff:1.2.3.4` → `1.2.3.4`) and zones are dropped. Malformed entries are skipped and never become the client IP.
- H-IP-4: The derived client IP is stored in the request context for logging and rate limiting.
- H-IP-5 (deployment contract): Caddy determines the client IP (trusting Cloudflare ranges, reading `CF-Connecting-IP`) and **overwrites** XFF with that single value when proxying. The web server MUST forward the caller's XFF on its server-side API fetches (Plan 2 obligation). The compose network is pinned to `172.30.0.0/24`; production sets `TRUSTED_PROXIES=172.30.0.0/24`. The API never reads `CF-Connecting-IP` itself.
- H-IP-6: When `APP_ENV=production` and `TRUSTED_PROXIES` is empty, the server logs a startup **warning** (behind a proxy, every user would share one rate-limit bucket).

## 5. Rate Limiting (H-RL)

Token bucket per client: a bucket refills at *rate* tokens/s up to *burst*; each request
takes one token; an empty bucket → 429.

- H-RL-1: Request classes: a path starting with `/api/v1/files/` is class **`files`**; `/healthz` is **exempt**; **every other path** (including unknown `/api/` routes, non-API paths, any method, HEAD) is class **`api`**. Each client has one bucket per class:

  | Class | Default rate | Default burst |
  |---|---|---|
  | `api` | 20 req/s | 100 |
  | `files` | 30 req/s | 300 |

  The defaults allow for many students sharing one campus NAT address.
- H-RL-2: Limited request → **429**, envelope `error.code = "rate_limited"`, `Retry-After` = `max(1, ceil(seconds until a token is available))`, computed with `Reserve()` and then `Cancel()` so the rejected request consumes nothing.
- H-RL-3: Client key: IPv4 address as is; IPv6 grouped by **/64** prefix (one household/phone typically owns a /64 and could otherwise rotate addresses).
- H-RL-4: Memory bound: a key whose buckets have been idle for **60 s** is evicted by a background sweep (an idle bucket has refilled completely, so forgetting it changes nothing). At most **100 000 keys** are tracked (each key holds both class buckets). When full: run a sweep; if still full, **new keys are not rate limited** (the concurrency caps still protect the server) and a warning is logged at most once per minute.
- H-RL-5: Configurable: `RATE_LIMIT_ENABLED` (default `true`), `RATE_LIMIT_API_RPS`/`_BURST`, `RATE_LIMIT_FILES_RPS`/`_BURST` (positive numbers; invalid → startup error).
- H-RL-6: Safe for concurrent use; the sweep goroutine stops on shutdown.
- H-RL-7 (Plan 2 obligation): the web app MUST configure PDF.js with `rangeChunkSize` ≥ 1 MiB (with the 64 KiB default a 25 MiB PDF needs ~400 requests, more than the files burst).

## 6. Concurrency Caps (H-CC)

- H-CC-1: At most `MAX_INFLIGHT_API` (default **32**) `api`-class requests run at once, and at most `MAX_INFLIGHT_FILES` (default **64**) file downloads stream at once. (32 is a few times the DB pool size, so requests are not left queueing inside the pool.)
- H-CC-2: At most `MAX_INFLIGHT_FILES_PER_CLIENT` (default **8**) concurrent file streams per client key; one more → **429** `rate_limited`, `Retry-After: 1`. Without this, one client could hold every download slot with slow downloads.
- H-CC-3: Over a global cap → immediately **503**, `error.code = "overloaded"`, `Retry-After: 1` (no queueing).
- H-CC-4: Caps are checked **after** rate limiting.

## 7. Database Limits (H-DB)

- H-DB-1: Connections of the **serving pool** have `statement_timeout = 5s` and `idle_in_transaction_session_timeout = 10s` (connection runtime parameters). Migrations and `cmd/seed` use a connection **without** these limits: the server runs migrations on a short-lived separate pool, then opens the serving pool.
- H-DB-2: Serving pool: `MaxConns` = `DB_MAX_CONNS` (default 10), `MinConns` 0, `MaxConnIdleTime` 5 min, `MaxConnLifetime` 1 h.
- H-DB-3: `api`-class requests carry a **10 s** context deadline. The database lookup of a file request has its own **2 s** deadline, so download floods can't starve JSON requests of connections. Streaming after the lookup is governed by H-HTTP-3.
- H-DB-4: One helper, `httpx.DBError(w, r, err)`, replaces `httpx.Internal` for database errors:
  - `errors.Is(err, context.DeadlineExceeded)`, `pgconn.Timeout(err)` or PostgreSQL SQLSTATE `57014` → **503** `timeout`, `Retry-After: 1`, logged at **warn**.
  - `errors.Is(err, context.Canceled)` (the client went away) → logged at **info**, nothing written.
  - anything else → 500 `internal`, as before.

## 8. HTTP Server Limits (H-HTTP)

- H-HTTP-1: `ReadHeaderTimeout` 5 s, `ReadTimeout` 15 s, `IdleTimeout` 60 s, `MaxHeaderBytes` 32 KiB (this also bounds the URL/query length). No global `WriteTimeout`.
- H-HTTP-2: `api`-class responses get a write deadline of **15 s**.
- H-HTTP-3: File downloads get a write deadline of `30 s + size ÷ 32 KiB/s` (25 MiB → 830 s ≈ 13.8 min). Clients averaging under 32 KiB/s are cut off.
- H-HTTP-4: Every per-response write deadline is **reset to "none" when the handler returns** (`defer rc.SetWriteDeadline(time.Time{})`). Without `WriteTimeout`, net/http does not reset deadlines between requests, so a deadline would otherwise linger on a reused keep-alive connection (e.g. Caddy's upstream pool) and break the next request.
- H-HTTP-5: Deadline calls must tolerate writers that don't support them (`http.ErrNotSupported`, e.g. test recorders).

## 9. Headers & Caching (H-HDR)

- H-HDR-1: Every response gets `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`; file responses replace it with their stricter `default-src 'none'; sandbox`. When the panic handler strips file headers, the default CSP is re-applied.
- H-HDR-2: Every response gets `Cross-Origin-Resource-Policy: same-origin`. It stops *other sites* from embedding our files/JSON (`<img>`, `<embed>`, no-cors fetch); it does not affect same-origin pages, server-side fetches, the PDF.js worker, navigation or OAuth redirects. If files ever move to another origin, this becomes `same-site`.
- H-HDR-3: Every error response (4xx/5xx JSON envelope) carries `Cache-Control: no-store`, so no cache (e.g. a Cloudflare "cache everything" rule) can store a 404/429/503.
- H-HDR-4: HSTS and compression are Caddy's job (Plan 7).

## 10. Health Check (H-HC)

- H-HC-1: `/healthz` reuses its last database-ping result for **2 s**, so polling it can never put more than one ping per 2 s on the database. Concurrent callers share one in-flight ping.
- H-HC-2: The server binary accepts `-healthcheck`: it requests `http://127.0.0.1:<port>/healthz` (port from `HTTP_ADDR`), exits 0 on 200 and 1 otherwise. Compose uses it as the API container's healthcheck (the distroless image has no curl).

## 11. Logging (H-LOG)

- H-LOG-1: Each request line includes `client_ip`.
- H-LOG-2: Rejected (429/503) requests are logged like any other — one line each, no extra lines.
- H-LOG-3: Docker logs are rotated: both services use `logging: {driver: local, options: {max-size: "10m", max-file: "5"}}` (≤ 50 MB per service).
- H-LOG-4 (Plan 7 obligation): logs containing IPs are retained ≤ 30 days.

## 12. Storage & Shutdown

- H-ST-1: `storage.Local.Put` calls `Sync` on the temp file before closing and renaming it.
- H-OPS-1: If graceful shutdown exceeds 10 s, open connections are force-closed (`Server.Close`) and the process exits 1. Compose sets `stop_grace_period: 20s` so Docker doesn't SIGKILL before that happens.

## 13. CI & Supply Chain (H-CI)

- H-CI-1: `permissions: contents: read`.
- H-CI-2: All third-party actions pinned by **commit SHA** (with a version comment).
- H-CI-3: `actions/setup-go` uses `go-version: '1.26.x'` with `check-latest: true`, matching the floating Docker tag.
- H-CI-4: CI runs `govulncheck` and `gosec -exclude-generated` at **pinned versions**; any finding fails the build. The current gosec findings are reviewed and annotated in place with `// #nosec <rule> -- <reason>`.
- H-CI-5: A weekly `schedule:` run catches newly published vulnerabilities without a code change.
- H-CI-6: Dependabot: weekly PRs for gomod (`/api`), docker (`/api`), github-actions (`/`).

## 14. Containers (H-CTR)

- H-CTR-1: `api`: `read_only: true`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `mem_limit: 256m`, `cpus: 1.0`, `pids_limit: 512`, `GOMEMLIMIT=200MiB`, healthcheck via H-HC-2, `stop_grace_period: 20s`.
- H-CTR-2: `postgres`: `security_opt: [no-new-privileges:true]`, `mem_limit: 512m`.
- H-CTR-3: The default compose network uses subnet `172.30.0.0/24` (H-IP-5).

## 15. Middleware order

```
clientIP → logRequests → recoverPanics → securityHeaders → rateLimit → inflight → deadlines → mux
```

Client IP is known before logging; rejected requests are logged and carry security
headers; rate limiting runs before the shared caps; deadlines wrap only work that passed.

## 17. API contract changes

New error codes `rate_limited` (429), `overloaded` (503), `timeout` (503), added to the
`Error.code` enum and as documented responses on every `/api/v1` operation.

## 18. Acceptance Criteria

| ID | Criterion |
|---|---|
| HAC-1 | `govulncheck ./...` reports no reachable vulnerabilities; `go.mod` says `go 1.26.6` |
| HAC-2 | Client IP: no trusted proxies → XFF ignored; trusted proxy → right-most untrusted XFF entry across multiple header lines; malformed entries skipped; `::ffff:a.b.c.d` unmapped; `[v6]:port` and bare IPs parsed |
| HAC-3 | Burst+1 requests from one IP → last is 429 `rate_limited`, `Retry-After ≥ 1`; another IP unaffected; a rejected request consumes no token |
| HAC-4 | Two IPv6 addresses in one /64 share a bucket; different /64s don't; a mapped IPv4 is keyed as IPv4 |
| HAC-5 | `api` and `files` buckets are independent; unknown `/api/` paths count as `api`; `/healthz` never limited |
| HAC-6 | Keys idle ≥ 60 s are evicted; with the table full, new keys pass unlimited and tracked keys never exceed the cap |
| HAC-7 | `RATE_LIMIT_ENABLED=false` disables limiting |
| HAC-8 | Global cap saturated → next request 503 `overloaded` immediately; per-client file cap → 429 |
| HAC-9 | Serving-pool connections report `statement_timeout = 5s`; `pg_sleep(6)` fails; the migration pool has no such limit |
| HAC-10 | A timed-out query → 503 `timeout` with `Retry-After`; a cancelled request writes nothing |
| HAC-11 | The HTTP server is built with the H-HTTP-1 values |
| HAC-12 | `api` responses get a ~15 s write deadline, files `30 s + size/32 KiB/s`; both are reset afterwards; two requests on one keep-alive connection, further apart than the deadline, both succeed |
| HAC-13 | H-HDR-1/2/3 headers present (and default CSP restored after a panic); file responses keep the sandbox CSP |
| HAC-14 | `/healthz` pings the database at most once per 2 s under concurrent calls; `-healthcheck` exits 0/1 correctly |
| HAC-15 | Request log lines contain `client_ip` |
| HAC-16 | Shutdown exceeding its timeout force-closes open connections and returns an error |
| HAC-17 | New configuration validated (bad number / bad CIDR → error); production warning when `TRUSTED_PROXIES` empty |
| HAC-18 | OpenAPI lists the new codes/statuses; contract test passes |
| HAC-19 | *(CI)* read-only permissions, SHA-pinned actions, govulncheck + gosec green, weekly schedule, Dependabot config |
| HAC-20 | *(manual)* `docker compose up --build` healthy with hardened settings; seed works; logs rotated |
| HAC-21 | *(manual)* Load test from one IP: excess gets 429 quickly; a second client's latency stays normal |

## 19. Decisions & Trade-offs

| Decision | Alternative | Why |
|---|---|---|
| In-process limiter | Redis | Single instance; no extra service |
| Reject over cap (503) | Queue | Queues hide overload; failing fast keeps the server healthy |
| Table full → new keys unlimited | Shared overflow bucket | A shared bucket lets an attacker who fills the table deny service to every new real user; the concurrency caps still bound total load |
| Caddy decides client IP | API reads `CF-Connecting-IP` | Only Caddy talks to Cloudflare; one place to trust |
| Health result cached 2 s | Own rate-limit bucket | Same protection for the DB, simpler |
| Log rotation only | Also sample 429 lines | Rotation already bounds disk use |
| Separate migration pool | `SET statement_timeout = 0` in migrations | Keeps the limit unconditional on the serving pool |
