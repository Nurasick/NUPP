# Plan 1.5 — Security & Resilience Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Implement the hardening spec: patched toolchain, client-IP derivation, rate limiting, concurrency caps, DB and HTTP timeouts, headers, health-check caching, container and CI hardening.

**Architecture:** Two new focused packages: `internal/clientip` (who is the client?) and `internal/ratelimit` (per-key token buckets with eviction). New middleware in `internal/server` composes them in the order fixed by spec §15. `internal/db` gains connection options so the serving pool carries limits while migrations don't. `httpx` gains `DBError` and `no-store` on errors.

**Tech Stack:** Go 1.26.6, `golang.org/x/time/rate`, `net/netip`, pgx v5 pool config.

**Spec:** `docs/superpowers/specs/2026-10-07-plan-1.5-hardening-spec.md` (v2, binding). This plan lists tasks and their tests; the spec holds every value.

## Global Constraints

- All Plan 1 constraints still hold (envelope, `[]` not null, wrapped errors, explanatory comments per R-DX-6).
- Every new behaviour gets a test that is watched failing first.
- Defaults exactly as spec §16. Middleware order exactly as spec §15.

## Review Focus

1. Forged or malformed `X-Forwarded-For` from an untrusted peer must never change the client key → Task 3 tests.
2. Write deadlines must not leak onto the next request of a keep-alive connection → Task 6 keep-alive test.
3. Table-full limiter must not lock out new real users → Task 4 test.
4. A client that disconnects mid-query must not produce a 500 or an error log → Task 7 test.
5. Error responses must never be cacheable → Task 5 test.
